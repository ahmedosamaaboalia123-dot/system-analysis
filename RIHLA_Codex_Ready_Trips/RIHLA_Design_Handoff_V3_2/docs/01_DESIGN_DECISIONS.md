# 01 — قرارات التصميم المعتمدة (Source of Truth)

## الغرض

هذا المستند يحدد **اتجاه تصميم التطبيق** الناتج عن مراجعات رحلة حتى V3.2. ليس وصفًا للأعمال الداخلية للموديولات.

## الهوية

- الاسم الرئيسي: **رحلة** فقط (من دون ERP).
- الشخصية: عربية عصرية، منظمة وهادئة ومناسبة لاستخدام إداري يومي.
- اللغة: العربية أولًا؛ RTL في كامل المنتج.
- الخط: **Almarai** فقط للواجهة العربية (300، 400، 700، 800).
- الألوان: الباليت Graphite التي اعتمدها المستخدم في التجربة الأخيرة. المصدر التنفيذي هو `tokens/rihla-tokens.json`.
- اللون الذهبي **مستبعد من الهوية**. يمكن استخدام الأصفر/الكهرماني فقط لحالة warning ذات معنى وظيفي، وليس في الشعار أو التزيين.
- اللوجو الحالي ليس نهائيًا. يستبدل لاحقًا دون تعديل الـ layout.
- أيقونات الـ Sidebar في معاينة V3.2 ليست نهائية؛ يجب استبدالها حسب أسماء الموديولات الحقيقية.

## التوزيع المعتمد لتطبيق Desktop

```text
┌──────────────────────┬─────────────────────────────────────────────┐
│ Sidebar (ثابت)       │ Header (ثابت 66px)                         │
│ 76px مختصر           ├─────────────────────────────────────────────┤
│ 254px موسّع          │ Main Workspace — منطقة التمرير الوحيدة     │
│ يبدأ بالأيقونات      │ بطاقات/جداول/نماذج                          │
│ وزر التوسيع بداخله   │ أعلى الصفحة: radius 22px يمينًا ويسارًا    │
│                      │ بعد بدء scroll: radius = 0                  │
└──────────────────────┴─────────────────────────────────────────────┘
```

- الـ Header والـ Sidebar يستمران بالظهور طوال التنقل والتمرير؛ لا يوجد Scroll للـ body في وضع Desktop المعتاد.
- خلفية الـ shell موحدة `#E4E9E6`. الـ Workspace أبيض بوضوح ويظهر منفصلًا عن الإطار.
- الـ Header يتبع هندسة معاينة V3.2: شريط قصير ومدمج، بحث مركزي، أدوات أساسية قليلة، قرب بصري من الـ Sidebar.
- الأدوات العلوية في المرجع تجريبية: البحث، الإضافة السريعة، الإشعارات، الحساب. وجودها وسلوكها النهائي مرتبط بإذن المستخدم والموديولات الفعلية.
- مساحة العمل عند أعلى التمرير لها استدارة في **الركنين العلويين معًا**؛ عندما تتجاوز `scrollTop > 2px` تختفي الاستدارة، وتعود عندما يصبح `scrollTop <= 2px`.
- الـ Sidebar افتراضيًا **مختصر بأيقونات**؛ الضغط على أيقونة ينقل للشاشة ولا يفتح التفاصيل. زر التوسيع فقط يتحكم بعرض أسماء الأقسام.
- حين تتوسع القائمة، تظهر المجموعات الفرعية بمؤشر سهم صغير يدور مع الفتح والإغلاق، ويمكن إغلاق المجموعة بالضغط على مساحة فارغة من القائمة.

## لغة التفاعل

- Hover يغيّر اللون **مؤقتًا فقط**.
- Active للتبويبات الرئيسية / عناصر التنقل يظهر **مستمرًا حتى تغيير الاختيار**.
- زر حفظ/إضافة/تعديل لا يبقى selected بعد الضغط لمجرد أنه ضُغط؛ يُظهر feedback ملائمًا.
- الأخطاء تكون داخل الـ input (indicator) وأسفله (message)، مع حالات focus/error واضحة.
- Dropdowns وCalendar مصممان وفق الهوية ولا يعتمدان على قائمة browser الزرقاء كمظهر أساسي.
- Alerts أربع حالات: Success / Info / Warning / Error، خلفيات واضحة وشريط رأسي **يمين** كل رسالة، بدون أيقونات كبيرة مزخرفة.
- الجداول والفلاتر تشمل أنماطًا للبحث والفرز وتحديد الصفوف وتغيير الأعمدة والكثافة والتصفح والتصدير؛ هذه تفاعلات UI مرجعية لا تعني وجود Backend فعلي.
- النماذج متعددة الخطوات، Modals، المرفقات، والتحقق والحفظ التجريبي جزء من مكتبة الأنماط.

## المسموح تغييره دون فتح قرار هوية جديد

- اللوجو النهائي ومشتقاته (مع حفظ حدوده/مساحة عرضه في الـ Shell).
- تعيين أيقونات واضحة ودقيقة لكل موديول حقيقي.
- تسميات الأقسام الفعلية وترتيبها بناء على مواصفات النظام المعتمدة.
- البيانات، المحتوى، الصلاحيات، الـ API endpoints وتفاصيل الأعمال.

## الممنوع تغييره بدون موافقة صريحة

- الخط العربي أو اللون الأساسي والباقي من الباليت.
- موضع Sidebar/هيكل Header/سلوك تمرير Workspace.
- الأصل Collapsed، وسلوك عدم التوسيع عند اختيار أيقونة.
- Adaptive radius، الـ RTL، الـ Alerts أو منطق Active/Hover.
- استبدال النظام بواجهة Zoom أو V3 Reference-inspired السابقة؛ تم رفض هذا الاتجاه وتم الرجوع لهوية رحلة الأصلية.
